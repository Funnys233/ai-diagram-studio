# 执行服务异常恢复

每次 SDK 执行在独立会话目录内保存 `execution.json`：启动前生成随机进程标识，
启动后保存 PID，收到正文时先保存回执，再推送到桥接。完成候选和子进程已退出的确认
分别保存，服务重启后无需重新发送模型请求。

桥接每 15 秒核对未知任务，读取时也触发核对；页面“恢复任务状态”允许立即检查。
只有确认原 SDK 已停止，才恢复完成结果或将中断任务标为失败并释放占位。
未知进程身份、无法读取元数据或停止失败继续保持待核对，不能用超时猜测已停止。

Windows 通过独立 node.exe 路径和执行标识核对 SDK，持有同一进程句柄、检查启动时间后
停止进程并等待退出；不按裸 PID 杀进程。仅精确验证的标准系统 conhost 属于显示辅助，
由 Windows 回收；路径、账号、父子关系、创建时间、非启动器参数或后代不符时保守拒绝。
当前 POSIX 实现仅对已消失进程作停止证明，存活孤儿保持未知；生产运行在 Windows。

网站提交丢失且远端返回 404 时，恢复接口先原子写入带账号和内容摘要的防重记录，
再释放网站占位，拦截可能迟到的原请求。恢复不包含原提示词，也不调用模型。
失败及取消保留网站已保存的正文；确认完成时使用持久化的完整结果。

旧版无执行回执的未知任务不能在运行中猜测恢复；需要暂停独立 worker，并证明专属
SDK 进程均已结束后做一次维护迁移。本次上线前确认旧版没有未结束任务。
本人订阅网关允许仍在核对且占有任务位的原任务继续生成，避免短暂网络抖动撤销推理。

验收包括本地模拟、网站至桥接集成，以及 `diagram-agent` 身份的 Windows 无模型测试。
